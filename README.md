Тема работы: Применение поведенческих паттернов проектирования «Посредник» и «Состояние» при разработке мини-системы принтера. Проектирование очереди печати документов.

Цель работы: Формирование практических навыков применения поведенческих
паттернов проектирования в рамках единой программной системы.


Паттерн «Состояние» (State)
Отвечает за: изменение поведения документа в зависимости от его текущего состояния.
Ключевые файлы: States/IDocumentState.cs, States/NewState.cs, States/PrintingState.cs, States/DoneState.cs, States/ErrorState.cs, Models/Document.cs


Как это работает в программе:
Когда вызывается doc.AddToQueue(), текущее состояние документа (например, NewState) решает, что делать. В NewState метод AddToQueue отправляет запрос посреднику: «добавь меня в очередь». Если документ уже напечатан (DoneState), метод AddToQueue выведет сообщение, что нельзя добавить.
 
--------------------------------------------------------------------------------------------------------

Паттерн «Посредник» (Mediator)
Отвечает за: координацию всех компонентов без прямых ссылок между ними.
Ключевые файлы: Mediator/IMediator.cs, Mediator/Colleague.cs, Mediator/PrintSystemMediator.cs, а также все классы в Models/


Как это работает в программе:
Ни один класс не вызывает методы другого напрямую. Например, Document не говорит printer.StartPrint(), а говорит mediator.Notify("RequestPrint"). Посредник уже сам решает, что делать: сменить состояние документа, вызвать printer.StartPrint(), потом обработать результат и т.д.
